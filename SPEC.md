## 1. Цель

Я замеряю голые фасадные стены на объекте (до облицовки) и потом переношу размеры в Autodesk Fusion. Сейчас переписываю цифры вручную — долго и бывают ошибки.

Приложение должно:
- быстро принимать размеры стены и проёмов на объекте, в дюймах с дробями, в перчатках;
- сразу рисовать стену в масштабе, чтобы ошибку в цифрах было видно на месте;
- хранить фото каждой стены;
- выгружать DXF, который вставляется во Fusion (Insert → Insert DXF) в масштабе 1:1 в дюймах.

## 2. Платформа и ограничения

- Основное устройство: **iPhone, Safari**, приложение добавлено на экран «Домой».
- Тип: PWA, одна страница, работает **полностью офлайн** после первой загрузки.
- Никакого сервера и аккаунтов: все данные хранятся на телефоне (IndexedDB).
- Технологии: ванильный JS (ES-модули можно), без npm-зависимостей в рантайме. Для тестов можно использовать Node без внешних пакетов (`node --test`).
- Интерфейс на **русском языке**. Названия стен, типы проёмов в DXF — латиницей (Fusion и цех).

## 3. Единицы и формат размеров

- Все размеры — **дюймы с дробями**.
- Точность настраивается: **1/16"** (по умолчанию) или **1/8"**.
- Внутри размеры хранятся как десятичное число дюймов (`48.375`). На экране всегда показываются дробью, округлённой до выбранной точности и сокращённой: `48 3/8"`, `1/4"`, `96"`.
- Ввод футов разрешён: `12' 4 1/2` → `148 1/2"`.

### Правила разбора ввода (парсер)

| Ввод | Результат (дюймы) |
|---|---|
| `48` | 48 |
| `48 3/8` | 48.375 |
| `3/8` | 0.375 |
| `12'` | 144 |
| `12' 4 1/2` | 148.5 |
| `12'4` | 148 |
| `48.5` | 48.5 |
| `48 4/16` | 48.25 (на экране `48 1/4"`) |
| пусто | null (не заполнено) |
| `48 3/0`, `abc`, `1/2/3` | ошибка, поле подсвечивается, значение не сохраняется |

Форматирование: `48.375` → `48 3/8"`; `0.0625` → `1/16"`; `47.999` при точности 1/16 → `48"`.

## 4. Модель данных

```
Project {
  id, name, address, date (YYYY-MM-DD), createdAt, updatedAt,
  walls: Wall[]
}
Wall {
  id, name ("North-1"), side ("N" | "S" | "E" | "W" | ""),
  width, height,          // дюймы, number | null
  photo,                  // dataURL JPEG или null
  notes,                  // свободный текст
  openings: Opening[]
}
Opening {
  id, type ("window" | "door" | "vent" | "other"),
  x, y, w, h              // дюймы, number | null
}
Settings { precision: 16 | 8 }
```

Система координат стены: **начало — левый нижний угол стены**, X вправо, Y вверх.
- `x` — от левого края стены до левого края проёма;
- `y` — от низа стены до низа проёма;
- `w`, `h` — ширина и высота проёма.

Эта подсказка должна быть видна в интерфейсе рядом с полями проёма.

## 5. Экраны

### 5.1 Список объектов
- Карточки объектов: название, адрес, дата, количество стен.
- Кнопка «+ Объект».
- Шестерёнка → настройки (точность 1/16 или 1/8), кнопка «Восстановить из резервной копии».

### 5.2 Объект
- Поля: название, адрес, дата (обычная клавиатура).
- Список стен: миниатюра схемы, имя, размер `W × H`, количество проёмов, значок ⚠ если есть ошибки.
- «+ Стена» — создаёт стену с именем по умолчанию (`Wall-1`, `Wall-2`…) и сразу открывает её.
- «Экспорт DXF (все стены)».
- «Резервная копия» — JSON всего объекта вместе с фото.
- «Удалить объект» — с подтверждением.

### 5.3 Стена (главный экран)
Сверху вниз:
1. Имя стены и сторона (кнопки N / S / E / W).
2. Фото: кнопка «Сфотографировать» (`<input type="file" accept="image/*" capture="environment">`). Миниатюра; по нажатию — на весь экран с зумом пальцами. Можно переснять или удалить.
3. **Схема стены в масштабе** (SVG):
   - контур стены; проёмы прямоугольниками с номером и подписью `W × H`;
   - общая ширина подписана сверху, высота — справа;
   - проёмы с ошибками — красные;
   - нажатие на проём на схеме прокручивает к его карточке;
   - если ширина/высота стены не введены — заглушка «Введи ширину и высоту».
4. Поля стены: **Ширина**, **Высота**.
5. Карточки проёмов: номер, тип (кнопки Окно / Дверь / Решётка / Другое), поля X, Y, W, H, текст ошибки, «Удалить».
6. «+ Проём» — добавляет проём и сразу открывает клавиатуру на его поле X.
7. Заметки к стене.
8. «Экспорт DXF (эта стена)».

## 6. Клавиатура для размеров (самое важное)

Системная клавиатура для размеров **не используется**. Нажатие на поле размера открывает свою клавиатуру снизу экрана (bottom sheet).

- Кнопки крупные, не меньше 56×56 pt, с отступами — для работы в перчатках и на солнце.
- Сверху: название поля («Проём 2 — Y»), набранный текст и рядом живой результат (`= 148 1/2"`) или «ошибка».
- Цифры 0–9, `'` (футы), `.`, ⌫, «Очистить».
- Ряд дробей: `1/8 1/4 3/8 1/2 5/8 3/4 7/8`.
- Если точность 1/16 — второй ряд: `1/16 3/16 5/16 7/16 9/16 11/16 13/16 15/16`.
- Нажатие на дробь **заменяет** уже набранную дробь (не дописывает вторую): набрал `48`, нажал `3/8` → `48 3/8`; нажал `1/2` → `48 1/2`.
- Кнопка **«Далее»**: сохраняет значение и переходит к следующему полю по порядку: Ширина → Высота → Проём 1: X → Y → W → H → Проём 2: X … После последнего поля клавиатура закрывается.
- Кнопка **«Готово»**: сохраняет и закрывает.
- Нажатие вне клавиатуры: сохраняет и закрывает.
- Схема обновляется сразу после сохранения каждого значения.
- Лёгкая вибрация при нажатии не нужна (на iPhone в вебе не работает) — вместо неё визуальная реакция кнопки.

## 7. Проверки (валидация)

Для каждого проёма, когда все нужные значения заполнены:
- выходит за стену: `x < 0`, `y < 0`, `x + w > width`, `y + h > height` → «Выходит за стену»;
- пересекается с другим проёмом (площадь пересечения > 0; касание краями — не ошибка) → «Перекрывается с проёмом N»;
- `w <= 0` или `h <= 0` → «Нулевой размер».

Незаполненные поля — не ошибка, а серый пунктирный проём на схеме (если хватает данных его нарисовать) или просто без отрисовки.

Ошибки **не блокируют** сохранение и экспорт — только подсвечиваются.

## 8. Экспорт DXF

- Формат: ASCII DXF, совместимый с Autodesk Fusion (Insert DXF). Рекомендую AutoCAD R12 (`AC1009`) с сущностями `LINE` — самый совместимый вариант; если выбираешь другую версию, обоснуй.
- Единицы: дюймы, 1 единица DXF = 1 дюйм. Прописать `$INSUNITS = 1` в заголовке (если версия формата это поддерживает).
- Слои:
  - `WALL` — контур стены (замкнутый прямоугольник из 4 линий), цвет 7;
  - `OPENINGS` — проёмы, цвет 1;
  - `TEXT` — подписи (имя стены над стеной, номер и тип проёма внутри), цвет 3.
- Геометрия: левый нижний угол стены в точке (0, 0), Y вверх — так же, как в приложении.
- Экспорт одной стены: файл `<Объект>_<Стена>.dxf`.
- Экспорт всех стен объекта: один файл `<Объект>_all.dxf`, стены стоят в ряд слева направо с зазором 24" между ними, каждая подписана.
- Стены без ширины/высоты в экспорт не попадают — показать предупреждение со списком пропущенных.
- Имена файлов: латиница, цифры, `-` и `_`; остальные символы заменить на `_`.
- Отдача файла: `navigator.share({ files: [...] })`, если доступно (на iPhone откроется меню «Поделиться»: Файлы, AirDrop, Почта). Иначе — обычное скачивание через ссылку.

## 9. Хранение, офлайн, резервные копии

- Данные — в IndexedDB. Сохранение после каждого изменения, без кнопки «Сохранить».
- Фото перед сохранением сжимать: длинная сторона не больше 1600 px, JPEG качество 0.75.
- Service worker кэширует все файлы приложения: после первой загрузки приложение открывается без интернета. Версию кэша менять при каждом изменении файлов, чтобы обновления доходили до телефона.
- iOS может удалить данные веб-приложения, поэтому:
  - резервная копия объекта в JSON (с фото) через `navigator.share` / скачивание;
  - восстановление из JSON в настройках (если объект с таким id уже есть — спросить: заменить или сохранить как копию);
  - вызвать `navigator.storage.persist()`, если доступно.

## 10. Требования под iPhone

- `manifest.webmanifest`: `name: "Site Measure"`, `short_name: "Measure"`, `display: "standalone"`, `start_url` и `scope` относительные (`./`), чтобы работать из подпапки GitHub Pages.
- `apple-touch-icon` — **PNG 180×180** (SVG iOS не берёт), плюс иконки 192 и 512 для манифеста. Иконка простая: контур стены с проёмом и рулетка, контрастная.
- `<meta name="apple-mobile-web-app-capable" content="yes">`, `apple-mobile-web-app-status-bar-style`, `viewport-fit=cover`, отступы `env(safe-area-inset-*)`, чтобы ничего не уходило под вырез и полоску «Домой».
- Текстовые поля — шрифт не меньше 16px (иначе Safari зумит страницу при фокусе).
- Убрать задержку и двойной тап-зум на кнопках (`touch-action: manipulation`).
- Высокий контраст, светлая тема, читается на солнце. Тёмную тему не делать в MVP.
- Проверить, что `navigator.share` с файлами вызывается **напрямую из обработчика нажатия** (иначе iOS блокирует).

## 11. Тесты

`node --test` без внешних зависимостей. Логику держать в отдельных модулях, чтобы её можно было тестировать без браузера:
- `units.js` — парсер и форматирование: все примеры из таблицы в разделе 3, обе точности, округление, сокращение дробей.
- `validate.js` — выход за стену, перекрытие, касание краями (не ошибка), незаполненные поля.
- `dxf.js` — структура файла (SECTION/ENDSEC, EOF), слои, координаты прямоугольников, раскладка нескольких стен с зазором 24", пропуск неполных стен.
- Если в окружении есть Python и `ezdxf`, дополнительно прочитать сгенерированный DXF через `ezdxf` и проверить, что он открывается без ошибок. Если нет — не устанавливать специально, просто написать об этом.

## 12. Критерии приёмки

1. На iPhone открываю ссылку в Safari → «Поделиться» → «На экран Домой» → приложение запускается на весь экран без адресной строки.
2. В авиарежиме приложение открывается, данные на месте.
3. Создаю объект и стену, ввожу `240` × `120`, проём `x 36, y 30 1/2, w 48, h 60` своей клавиатурой, не касаясь системной. Схема показывает проём в правильном месте.
4. Ввожу проём, вылезающий за стену, — он красный и с текстом ошибки.
5. Фото стены сохраняется и остаётся после перезапуска приложения.
6. «Экспорт DXF» → «Сохранить в Файлы». Во Fusion: Insert DXF, единицы inch — стена 240" × 120", проём на своём месте, размеры совпадают.
7. Резервная копия → удаляю объект → восстанавливаю из файла → всё вернулось, включая фото.

## 13. Не входит в MVP (следующие этапы)

- Bluetooth-дальномер (Leica DISTO / Bosch GLM). В Safari на iPhone Web Bluetooth не работает; варианты на потом — режим клавиатуры у дальномера или нативное приложение.
- Подписи размеров прямо на фото.
- Скрипт для Fusion (Python API), который строит параметрический эскиз из JSON.
- Экспорт CSV и PDF-отчёт (формат US Letter).
- Стены непрямоугольной формы.
- Синхронизация между устройствами.
